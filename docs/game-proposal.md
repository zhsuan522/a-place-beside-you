# 《換個地方陪著你》遊戲企劃書

**版本：** 0.1｜訪談確認稿  
**日期：** 2026-10-27  
**專案型態：** 手機瀏覽器優先的網頁互動遊戲，支援桌機  
**目前進度：** 階段 1 素材挑選已完成；階段 2 已有可玩本機原型。正式 MVP 尚待帳號、雲端同步、私有伺服器儲存及伺服器端計時。

## 1. 企劃定位

《換個地方陪著你》是一款以寵物離世紀念與情緒陪伴為主的私人互動作品。玩家把毛孩生前喜歡的地方想像成星球，安排一趟旅程，之後收到一張毛孩寄回的明信片，慢慢把旅程與回憶收進星圖和相簿。

本作不設定課程學習目標，不用答題、排名或成就衡量玩家。旅程選擇沒有正誤，不消耗資源；玩家何時回來、是否寫字、是否開啟通知，都不影響遊戲進度。

## 2. 目標玩家與平台

- **目標玩家：** 經歷過寵物離世的 16–17 歲青少年及成人。
- **主要平台：** 手機瀏覽器優先，並支援桌機瀏覽器。
- **呈現方式：** 開啟網站後直接進入遊戲中的「星空小樹屋」，不另做遊戲外的首頁。
- **帳號與保存：** 需要帳號，資料跨裝置保存；預設只有玩家本人可看。

## 3. 玩家體驗原則

1. **陪伴，不催促：** 旅程按真實時間等待；玩家晚回來不會錯過、受罰或失去內容。
2. **每次只有一趟：** 一趟旅程完成後只產生一張待讀明信片；讀完後才能安排下一趟。
3. **選擇沒有代價：** 星球、補給與旅程時間不消耗遊戲資源，也不設錯誤選項。
4. **文字是私人的：** 情境描述和可選信件留在玩家自己的毛孩資料與相簿，不公開，也不要求毛孩回信。
5. **由玩家決定距離：** 上傳照片、寫字、開啟瀏覽器通知都由玩家自行選擇。
6. **想像保持溫柔：** 以星際旅程作為紀念想像，不替玩家解釋生死或要求特定哀傷方式。

## 4. 世界與主要畫面

### 星空小樹屋

星空小樹屋是登入後的遊戲主畫面。毛孩在此休息，玩家可前往三個主要功能：

- **信箱：** 查看是否有待讀明信片；同一時間最多一張待讀卡片。
- **星圖：** 查看已建立的星球、旅程狀態與走過的路線。
- **相簿：** 保存毛孩資料、玩家的私人紀念文字、已讀明信片與收集到的紀念品。

介面以手機直向操作為優先，按鈕和文字欄位需適合觸控；桌機畫面可利用較寬空間呈現樹屋與星圖。

## 5. 核心玩法與流程

### 建立毛孩資料

玩家建立帳號並新增毛孩資料，可上傳自己的毛孩照片。照片只用於毛孩資料與相簿；明信片使用遊戲插畫，不把玩家照片合成進明信片。玩家可以下載或刪除自己的照片與紀念資料。

### 安排一趟旅程

1. 玩家從星圖選一個星球，或依毛孩生前喜歡的地方建立新星球。
2. 玩家可寫一小段場景描述，作為自己的私人紀念文字；可再從預製場景類型中，親自挑選最符合的一種，例如海邊或森林。場景由玩家選，不依賴系統猜測文字意思。
3. 玩家選一項補給。補給不消耗、不限制後續選擇，只影響這趟旅程的明信片與紀念品。
4. 玩家可寫一封信，也可以略過。信件是私人紀念文字，不會收到回信，也不影響旅程。
5. 玩家選擇 **6、12 或 24 小時**，開始旅程。

### 旅程完成與閱讀

1. 旅程按選定的真實時間完成；玩家關閉瀏覽器或沒有立即回來，不會中斷或重設計時。
2. 完成時在信箱放入一張對應該星球和補給的明信片，以及一件紀念品。待讀期間不會自動開始下一趟，也不會累積其他待讀卡片。
3. 玩家回來閱讀明信片後，明信片、紀念品及相關旅程資料收進相簿和星圖。
4. **閱讀明信片後才解鎖下一趟旅程。** 玩家可選擇回信、留下紀念，或做一個照顧自己的小回應；這些互動都可略過，不阻止下一趟。

### 狀態規則

`可安排旅程 → 旅途中 → 一張明信片待讀 → 已閱讀並收進相簿 → 可安排下一趟`

全程沒有生命值、倒數懲罰、登入連續天數、資源消耗或失敗狀態。旅程時間只決定何時可以讀卡，不評價玩家有沒有準時回來。

## 6. 明信片與素材內容規則

- 預製場景插畫對應玩家親自挑選的場景類型；第一版先涵蓋少量易辨識的場景。
- 星球場景和補給共同影響明信片文字細節與紀念品類型，所有組合都能完成旅程。
- MVP 建議以人工撰寫的短文模板及明確對照表產生內容，讓文字風格一致、內容可檢查；不需要 AI 解讀玩家的私人文字。
- 明信片使用遊戲插畫。Kenney 素材先支援 MVP，之後再逐步替換成手繪插畫。
- 素材包、精確的場景分類、補給清單與明信片文字，需在素材挑選階段實際選定；本企劃不把尚未挑選的素材寫成已定案。

## 7. 隱私與保存需求

- 毛孩照片、情境描述、信件、旅程與明信片預設只有帳號本人可存取。
- 登入後跨裝置同步毛孩資料、目前旅程狀態、待讀明信片、相簿和星圖。
- 玩家可自行下載及刪除照片與私人紀念內容；刪除帳號時也要清楚說明相關資料如何一併刪除。
- 不建立公開相簿、社群動態或排行榜。
- 正式上線前確認 16–17 歲玩家的帳號與資料流程，以及資料保存和刪除說明。

## 8. MVP 範圍與完成條件

### MVP 必須包含

- 手機瀏覽器優先的遊戲畫面，桌機可使用；進入網站直接看到星空小樹屋。
- 帳號登入及跨裝置雲端保存。
- 毛孩資料與私人照片上傳、下載、刪除。
- 信箱、星圖、相簿三個入口。
- 一趟旅程的完整流程：選星球、填寫或略過場景描述、手動選預製場景、選一項免費補給、可選寫信、選 6／12／24 小時。
- 關閉瀏覽器後仍能依真實時間完成旅程；完成後只建立一張待讀明信片。
- 待讀明信片必須先閱讀，才能安排下一趟；閱讀後將明信片與紀念品保存至相簿／星圖。
- Kenney 素材、少量預製場景、少量補給及足以走完流程的明信片內容。
- 不登入社群、不公開玩家內容、不加入遊戲貨幣或連續登入獎勵。

### MVP 驗收條件

- 玩家能從小樹屋開始、完成一趟旅程、收到並閱讀一張明信片，再安排下一趟。
- 選擇 6／12／24 小時後，即使玩家關閉瀏覽器，完成時間仍正確。
- 旅途中不能重複安排；有待讀明信片時不能開始下一趟；同時不會出現第二張待讀明信片。
- 星球場景及補給能反映在明信片或紀念品中，沒有選擇會造成失敗或扣除資源。
- 同一帳號換裝置後，仍能看到相同的旅程、待讀狀態與相簿內容。
- 私人文字與照片不會出現在其他帳號的內容中；玩家能找到下載及刪除入口。
- 手機觸控流程可完成，桌機版不會因版面尺寸而阻止遊戲操作。

## 9. 實作步驟

### 階段 1：完成素材挑選（先於 MVP）

1. 依星空小樹屋、星球場景、毛孩角色、明信片、紀念品及介面整理素材需求清單。
2. 使用專案中的 Kenney 素材技能尋找候選包，逐項確認視覺風格、檔案格式、使用授權和修改需求。
3. 挑出 MVP 實際使用的背景、角色、場景、圖示、UI 與字體素材；以手機尺寸和桌機尺寸檢查辨識度及可讀性。
4. 建立素材清冊，記下素材名稱、來源、授權、檔案路徑、遊戲用途及日後替換位置。
5. 完成後固定 MVP 素材清單，並放入既有 `public/assets/` 分類中。此階段完成前不開始 MVP 的視覺與場景實作。

**挑選結果：** 已選 Background Elements Remastered、Planets、UI Pack - Adventure、Generic Items 四包 Kenney CC0 素材。MVP 先做森林與海岸兩種場景；星空小樹屋以樹與小屋素材組合，星星、海面和部分 UI 圖示用 Phaser 圖形補足。完整路徑、授權檔與素材清冊見 [MVP 素材挑選清冊](asset-selection.md) 和 `public/assets/data/kenney-assets.json`。

### 階段 2：完成 MVP（素材挑選之後、迭代之前）

1. 確認帳號、資料庫、照片私有儲存及跨裝置同步方案；設定每位玩家只能存取自己的資料。
2. 定義毛孩、星球、旅程、待讀明信片、已讀明信片與紀念品的資料欄位及狀態轉換。
3. 以 Phaser 4 建立星空小樹屋與遊戲場景；較長文字輸入及帳號表單採用適合手機鍵盤與輔助技術的網頁表單。
4. 實作單趟旅程狀態和 6／12／24 小時的真實時間計時。伺服器保存旅程開始與預定完成時間，不能只靠瀏覽器計時器。
5. 實作玩家手選場景、補給對照、可略過的信件，以及一張待讀明信片和閱讀後歸檔的規則。
6. 串起登入、毛孩資料、照片上傳／下載／刪除、相簿和星圖保存。
7. 用已挑選的 Kenney 素材填入完整遊戲流程，檢查手機與桌機操作、回來逾時情境、跨裝置同步及私有資料權限。
8. 達成 MVP 驗收條件後，再開始下一階段迭代。

### 階段 3：第一次迭代——內容與流程打磨

- 擴充星球場景、補給、明信片及紀念品的組合，避免相同內容太快重複。
- 根據自願提供的玩家回饋，調整書寫提示、閱讀節奏、文字長度及回應選項。
- 改善星圖導覽、手機版觸控區域、字體大小、色彩對比與鍵盤操作。
- 以「玩家是否清楚理解流程、是否感到有選擇且不受催促」作為檢視方向；不以登入頻率或停留時間作為核心目標。

### 階段 4：第二次迭代——可選通知與安裝體驗

- 加入玩家主動開啟的瀏覽器通知；通知只提醒「有一張明信片可以閱讀」，不催促玩家回來。
- 信箱仍是待讀狀態的唯一依據；不允許通知失敗影響旅程或明信片。
- 先做瀏覽器功能偵測，再提供符合裝置情況的啟用說明。iPhone／iPad 的 Web Push 需使用加入主畫面的網頁 App，且權限請求須由玩家直接操作觸發；因此列為 MVP 後的選配工作。[Apple Developer](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers?language=objc)、[WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。

### 階段 5：第三次迭代——美術與長期內容

- 逐步將 Kenney 佔位或組合素材替換成手繪場景、毛孩動作、明信片及紀念品。
- 持續新增星球與回憶內容，但維持一次一趟和一張待讀卡片的節奏。
- 視玩家需要再評估環境音、朗讀、字級調整、更多語言或離線閱讀等功能；每項都先確認是否符合安靜、私人、無催促的定位。

## 10. 暫不納入 MVP 的功能

- 同時安排多趟旅程、自動連續出發或累積多張待讀明信片。
- 公開分享、好友互動、排行榜、連續登入獎勵、體力與付費抽取。
- AI 自動解析私人文字或生成毛孩回信。
- 瀏覽器推播通知與手繪全套美術；先以 Kenney 素材完成 MVP。

## 11. 待開發前確認的項目

- 明信片文字模板與 Generic Items 圖集中的實際補給／紀念品圖示對照。
- 帳號驗證、雲端資料庫、私有照片儲存和正式部署服務的選擇。
- 玩家刪除帳號時，照片、私人文字及旅程資料的刪除流程與說明。
- 「情境描述」欄位是否和可選信件一樣可略過。目前依低壓力原則規劃為可略過；若你希望每趟都必須寫，再調整流程。
