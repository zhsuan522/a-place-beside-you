# 遊戲式學習設計與製作

讓遊戲中的選擇和結果承載學習。故事、分數、徽章或動畫可以增加投入，但本身不能證明玩家學會了。

## 開始前

- 先查看專案目前使用的框架、入口、元件、素材和執行方式；沿用既有架構，避免無必要地重建。
- 確認學習者、學習主題、使用情境、遊玩時間、裝置或技術限制。缺少資料但仍可合理開始時，標明假設並做出可玩的初版；只有關鍵選擇會明顯改變作品時才提問。
- 若使用者要求製作或建立遊戲，完成可玩的實作；只有在使用者要求規劃或構想時，才停在設計稿。

## 設計流程

### 1. 先寫出可觀察的學習表現

把「了解／學會某主題」改寫為玩家在特定條件下能做出的動作，以及判斷表現的證據。例如：在有限預算與三回合供水條件下，比較修管線和購水方案，並根據水量及成本說明取捨。區分記憶、程序操作、概念解釋、證據推理、策略選擇和遷移應用，讓任務和證據符合真正要練習的能力。

### 2. 依思考活動選擇玩法

先決定學習者需要做什麼，再挑選合適形式，例如問答、謎題、分支情境、角色扮演、策略管理或模擬。只有在遊戲目標、規則、選擇和結果能提供必要練習時，才把活動做成遊戲；加入積分或徽章不會自動把原活動變成有效的遊戲式學習。選用數位功能時，確認它是否有助於呈現狀態、計算結果、比較方案、保存歷程、協作或提供回饋。

### 3. 建立清楚的核心循環

以「查看狀態 → 做出選擇 → 依規則計算結果 → 解讀結果並調整策略 → 進入下一回合」組成主要循環。明確定義：

- **狀態：** 玩家需要觀察的資訊，例如資源、預算、需求、時間或進度。
- **行動：** 玩家能採取的措施，以及每項措施的成本或限制。
- **規則：** 行動如何改變狀態，規則要足以支持有意義的比較與推理。

讓學習內容成為解決問題所需的依據，而非只出現在無關的故事或遊戲前測驗。控制同時變動的條件，讓玩家能看出決策和結果的關係；需要理解因果時，提供可比較的情境或行動紀錄。

### 4. 讓選擇有取捨，讓回饋說明原因

玩家應知道任務目標、可用行動及相關狀態。好的選擇會因成本、時間、風險或未來效果產生可解釋的差異。行動後呈現哪些狀態改變、改變多少，以及規則如何造成結果；可先給提示，再依學習目標決定是否揭示答案。只顯示分數或「答對／答錯」時，補上能幫助玩家檢查假設、修正策略的資訊。

設計時分清三種用途：回饋解釋行動和結果，獎勵提供遊戲內的肯定或資源，評量則根據表現判斷是否達成學習目標。檢查高分策略是否真的要求目標能力，避免獎勵誘使玩家跳過思考或只追求短期產量。

### 5. 安排挑戰、重試與支援

先用少量關鍵選項教會基本規則，再逐步增加限制、資訊來源或變動條件。挑戰應讓玩家需要思考，但仍能利用遊戲內資訊預測、檢查和解釋結果。讓失敗能帶來資訊，並提供查看歷程、比較結果和重新嘗試的機會。依困難來源提供示範、提示、圖表標記或部分步驟；玩家熟練後逐步撤除支援。

不要只依年齡推定經驗或能力。考慮閱讀負擔、操作熟悉度、裝置和環境差異；重要資訊使用清楚文字、標籤、單位和圖表，避免只靠顏色傳達，也考慮鍵盤操作、字幕和可調整節奏。

## 製作與交付

- 在既有專案中先完成最小可玩版本，優先實作一個完整的學習循環，再擴充關卡、故事或美術。
- 設計或實作完成後，確認玩家能開始遊戲、採取關鍵行動、看見結果並重試；遇到未完成或不可玩的部分要明確指出。
- 回覆設計成果時，簡要列出學習目標、核心循環、回饋／學習證據和重要假設。回覆實作成果時，說明完成了哪些玩法、如何啟動，以及哪些機制對應哪些學習目標。

## 完成前檢查

- 玩家是否真的要運用目標知識做決策或解釋？
- 狀態、行動、規則和結果是否看得懂，結果是否能支持推理？
- 回饋是否幫助玩家理解原因；獎勵與評量是否各有清楚用途？
- 難度是否逐步增加，失敗後能否學習、重試，支援是否能隨熟練度減少？
- 遊戲完成或得高分是否足以代表學習？若不足，補上能看出解釋、比較或遷移能力的證據。
